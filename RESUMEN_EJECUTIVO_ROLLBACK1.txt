SOLUCIONES PROPUESTAS
=============================================================================

OPCIÓN A (RECOMENDADA): Detección bidireccional

Modificar posicionDelEnlaceEnRuta() para buscar AMBAS direcciones:

```java
private static int posicionDelEnlaceEnRuta(EstablishedRoute route, Link link) {
    int from = link.getFrom();
    int to = link.getTo();
    List<Link> path = route.getPath();
    
    for (int i = 0; i < path.size(); i++) {
        Link li = path.get(i);
        // Buscar dirección directa O inversa
        if ((li.getFrom() == from && li.getTo() == to) ||
            (li.getFrom() == to && li.getTo() == from)) {
            return i;
        }
    }
    return -1;
}
```

VENTAJAS:
+ Fix mínimo, bajo riesgo
+ Mantiene arquitectura de cores compartidos
+ Soluciona ROLLBACK-1 y desplome de algoritmos

DESVENTAJAS:
- No resuelve el acoplamiento conceptual entre direcciones

OPCIÓN B: Separar cores entre direcciones

Crear List<Core> independientes para cada enlace direccional:

```java
List<Core> coresForward = createCores(numberOfCores, fsWidth, capacity);
List<Core> coresBackward = createCores(numberOfCores, fsWidth, capacity);
Link linkForward = new Link(distance, coresForward, vertex, connection);
Link linkBackward = new Link(distance, coresBackward, connection, vertex);
```

Sincronizar en assignFs/deallocateFs cuando sea necesario.

VENTAJAS:
+ Separación conceptual clara
+ Elimina acoplamiento físico
+ Más predecible para futuras extensiones

DESVENTAJAS:
- Cambio arquitectural mayor
- Requiere sincronización explícita
- Mayor complejidad en assignFs/deallocateFs
